# Цифровой двойник завода «Аляска» (Blender + Godot)

Открыть: **https://iliafreedive-del.github.io/factory/twin/**. Старая игра остаётся по своей ссылке
(`/factory/`, файл `index.html` в корне), двойник её не трогает.

## Зачем

Видеть весь завод на одном экране и решать, куда его развивать, на модели, а не на живом производстве:
где сейчас рамы, где очередь и простой, что будет, если переставить участок, добавить пост или поднять план.
Подробно: кнопка «Зачем это?» в двойнике и раздел «Зачем собственнику цифровая копия завода» в реестре.

## Что умеет

- Завод в 3D: здания, дворы, станки, люди. Геометрия взята из старой игры, которую сверяли с фото в PR 2–21,
  поэтому места те же. Сверху наложены материалы (профлист, кирпич, бетонные панели, плиты, асфальт, грунт,
  оцинковка, ржавчина), затенение углов запечено в Blender, свет и небо «как на фото 26.10» (пасмурно).
- Виды: обзор, сверху (север вверху, как на 2ГИС), с земли (WASD), 99 точек фото с тем же объективом.
- Крыши: авто (пропадают при приближении), сняты, на месте. Снятая крыша продолжает давать тень.
- «Путь рамы»: резка → сварка → ждут пескоструй → пескоструй → малярка → ждут распределения → сборка 1 и 2 → отправка.
  Рамы лежат стопками в очередях, кары везут их по маршрутам, у каждого участка загрузка цветом.
- «Параметры»: посты и минуты на раму по участкам, план, длина смены, скорость кары. **Все времена условные**, пока нет цифр с завода.
- «Пути развития»: варианты «что будет, если» (план 14, второй пост малярки, ещё один сварщик, Сборка 2 в строящемся цехе,
  18 рам в смену). Модель прогоняет смену и показывает узкое место, нехватку постов и пробег рамы.
- «Планировщик»: тянуть мышью участки, точки маршрута, целые здания и новые предметы (стопка рам, прицеп, контейнер,
  стеллаж, верстак, кара, цех 30×12). Линейка, отмена, варианты в браузере и файлом JSON.
- «Камеры»: камеры наблюдения, которые уже висят (фото 08.11, IMG_2320–2326). Места примерные.
- Ссылки на вид: `#IMG_1751` (точка фото), `#v=tx,tz,az,el,dist`, `#top`.

## Поток событий «состояние завода»

Всё, что видно на экране, рисуется из одного потока событий. Сейчас его даёт симуляция (`godot/scripts/sim.gd`),
потом тот же поток пойдёт с завода. Подключение: `…/twin/?live=wss://сервер/поток`, по одному JSON-событию
(или массиву событий) в сообщении WebSocket.

```json
{"t": 1731052800, "src": "cam", "type": "frame.enter", "zone": "sand", "id": "Р-017"}
```

| type | поля | откуда на заводе |
|---|---|---|
| `frame.enter` / `frame.leave` | zone, id | камера по зоне: рама въехала и выехала (песко, малярка, площадки) |
| `frame.move` | id, from, to, sec | кара или погрузчик везёт раму между зонами |
| `work.start` / `work.finish` | zone, id, post | операция на посту |
| `machine.power` | zone, machine, on, amps | датчик тока на станке: работает или простой |
| `batch.start` / `batch.done` | zone, batch, qty | сменное задание партией (резка, сварка) из 1С или с планшета мастера |
| `vin.read` | zone, vin, cam | VIN или шильдик прочитан на входе в сборку или на отгрузке |
| `person.count` | zone, n, cam | сколько людей в зоне по камере |
| `zone.status` | zone, status, note | работает, простой, стоит |
| `frame.done` | id | рама уехала с завода |

Зоны: `cut`, `weld`, `waitSand`, `sand`, `paint`, `distrib`, `asm1`, `asm2`, `ship1`.

Без QR-кодов и меток на деталях. До покраски на раме ничего нет: пескоструй всё снимает, поэтому раму ведут камеры
по зонам. VIN появляется после малярки, его читает камера на входе в сборку и на отгрузке. Металл и комплектующие
берутся из 1С. Начинать можно с потока RTSP с уже висящих камер; для VIN нужны 1–2 новые IP-камеры.

## Как собрано

```
twin/
  index.html, index.js, index.wasm, index.pck   веб-сборка Godot (то, что открывается по ссылке)
  blender/build_factory.py     сцена старой игры → классы материалов, цвет и затенение в вершинах → factory.blend + factory.glb
  blender/factory.blend        отдельный проект Blender (не связан ни с какими другими проектами)
  blender/export_glb.py        выгрузить factory.glb из factory.blend (3 секунды)
  tools/export_old_scene.js    снимок сцены index.html в Playwright: old_scene.glb + meta.json
  tools/make_twin_data.py      данные двойника: plan/plan.json + meta.json → godot/data/twin.json
  tools/make_textures.py       бесшовные текстуры в реальных метрах → godot/textures/
  godot/                       проект Godot 4.7 (Compatibility, веб без потоков для GitHub Pages)
    scripts/main.gd    сцена, свет, слои, карточки, цифры, «Зачем это?», «Пути развития»
    scripts/state.gd   «состояние завода»: поток событий, живой WebSocket
    scripts/sim.gd     симуляция пути рамы (условные времена), расчёт пропускной способности
    scripts/viz.gd     участки, стопки рам, кары, маршруты, камеры
    scripts/planner.gd планировщик
    scripts/ui.gd      интерфейс
    scripts/cam.gd     камера: облёт, сверху, с земли, точки фото
    scripts/mats.gd    материалы
    fonts/DejaVuSans.ttf  значки и стрелки для веб-версии (свободная лицензия, DejaVu-LICENSE.txt)
```

Пересборка после правок:

```sh
# 1) если менялась старая игра (index.html): новый снимок сцены и данные
node twin/tools/export_old_scene.js WORK
blender -b -P twin/blender/build_factory.py -- WORK/old_scene.glb WORK/factory.glb twin/blender/factory.blend
python3 twin/tools/make_twin_data.py WORK/meta.json
# 2) сцена для Godot из factory.blend
blender -b twin/blender/factory.blend -P twin/blender/export_glb.py -- twin/godot/assets/factory.glb
# 3) веб-сборка в twin/
cd twin/godot && godot --headless --import --path . && godot --headless --path . --export-release Web ../index.html
```

Снимки экрана без окна (сверка с фото): `xvfb-run godot --rendering-driver opengl3 --path twin/godot -- --shot=путь --views="photo2;photo4"`.

Фото и скриншоты Ильи в открытый репозиторий не кладём: они лежат в файлах проекта, в двойнике только номера фото.
